Architecture — on the enterprise Agentic Platform

Every component maps to the client's existing Agentic Platform. Nothing built outside the approved stack. Code lives in client-hosted GitLab.

① Discover

  • Agent Catalog — register "Demand Pattern RCA Agent"
  • Tools Catalog (MCP) — adherence, wow, plan-bias, peer, holiday, volume tools
  • Alation — catalog metric views + metric defs

② Security

  • Guardrails — block unsafe I/O; reject numbers not backed by a tool
  • Kong — SSO + API gateway on every call

③·④ Agentic Platform

  • RCA agent on LangGraph
  • Connectors: SQL Server (source), ServiceNow (escalation)
  • Framework: LangGraph

⑤ LLMs & Embeddings

  • In use today: Groq (Llama 3.3 70B), NVIDIA (Nemotron 3 Super 120B default), Gemini (gemini-3.6-flash default)
  • Embeddings: nomic-embed-text, for RAG over the probing KB if required

⑥ Interoperability

  • MCP Server hosts RCA tools
  • A2A protocol for agent-to-agent

⑦ Intent Orchestrator

  • Routes "why did <CQN> miss?" → RCA agent
  • Parses the queue/week/dimension out of the question, not just keyword-matches "why"
  • Disambiguates multi-queue asks (e.g. a Combined Queue spanning several Forecast_names) before handing off, instead of guessing one
  • Carries the resolved queue/week key forward so the RCA agent never has to re-ask what was meant

⑧ AI Ready Data

  • Metric views (adherence, WoW, flags)
  • Source: SQL Server → AI Ready Data

⑨ Agentic Memory

  • Today: session queue/week + confirmed known-causes (probing KB)
  • Next: persist the Evidence Pack per queue (miss-run length, plan-reissue history, holiday sensitivity) so a repeat investigation starts from what's already known instead of recomputing it
  • Next: remember which ranked causes a forecaster confirmed or rejected per queue, so the same wrong hypothesis isn't re-surfaced next time that queue misses
  • Next: cross-queue memory — once a cause is confirmed for one queue in a Combined Queue, surface it as a prior for its siblings before re-deriving from scratch

⑩ Deploy · Publish · Observe

  • GitLab CI/CD (client-hosted repos)
  • Langfuse · Splunk
  • Results → Data Mesh

Runtime flow

  • UI (custom, via Kong) → Intent Orchestrator receives intent
  • Guardrails checks input → RCA agent (LangGraph) clarifies scope
  • Agent calls deterministic MCP tools → query AI Ready Data
  • Reasons with the active provider (NVIDIA / Groq / Gemini); remembers via Agentic Memory
  • Output filtered by Guardrails → back through Kong → traced in Langfuse/Splunk

Data & Files

What we ingest, the grain, and the domain meaning of each field.

File types accepted

  • .xlsx (Excel) — parsed in-browser, no libraries
  • .csv / .tsv — delimiter auto-detected
  • Weekly demand file + optional CQN mapping file

Grain & key

  • Keyed on Forecast_name × Fiscal_Week
  • Forecasting is based on Forecast_name
  • Mapping file (optional) resolves sequence → Forecast_name

Scale

  • Live table dbo.Input_To_ML_Full — 88,816 rows, with real Channel (Voice / Chat / Email / Case / Social Media) and Offering (Basic / Pro / OOP / Premium) diversity
  • Handles 100k+ rows with chunked parsing
  • Top-N affected queues surfaced

Domain knowledge

  • Final_Y1–Y5 = installed units under warranty year 1–5 (demand driver, not prior-year actuals)
  • ASU = Planned/Actual service driver (exact acronym to confirm)
  • Mon–Sun = day-level holiday/weekend flags

Scope

  • Keyed on Forecast_name — forecasting is per forecast_name
  • Priority: 2–3 forecast_names, not the whole file
  • Filter to the target forecast_names, then read RCA

Drill-down / Scope card

  • Ladder recomputed live from SQL: Region → SubRegion → Country → Offering → Channel (Business Org included but filtered from the card — constant across the file)
  • Shows whether a miss is inherited from a wider level or concentrated at one queue
  • Also detects a Demand Switch — volume moving between Offerings/Channels rather than genuinely changing

Metrics (only these two)

  • Forecast Accuracy = (Actual_Offered ÷ fcst_offered) × 100
  • Plan Adherence = (1 − Actual_Offered ÷ fcst_offered) × 100 — signed (negative = under-forecast, positive = over-forecast)
  • Flag when |Plan Adherence deviation| > band %

Definitions & Formulas

Field headings, meaning, and the exact formula each rule-based tool computes.

Formulas — the only two computed

MetricExcelPython (rule-based tool)
Forecast Accuracy=(Actual_Offered / fcst_offered) * 100(actual_offered / fcst_offered) * 100
Forecast Adherence=IF(Actual_Offered="","",(1-(Actual_Offered/fcst_offered))*100)"" if actual_offered=="" else (1-(actual_offered/fcst_offered))*100
Forecast = fcst_offered. Keyed on Forecast_name. Both shown as %. Forecast Accuracy is the traditional formula; Forecast Adherence is the formula used in the current Excel system — signed (negative = actual ran above forecast / under-forecast, positive = actual ran below forecast / over-forecast). Flag = accuracy outside ±10% (≡ |forecast-adherence| > 10%). No other formulas are computed — nothing is inferred or invented.
